# 3 元精简收尾记录

本轮按用户明确批准的计划实施：官方技术资料、两组各 12 题、Agent 单独评分、一次集中工程回归及同一隔离栈的浏览器流程。总预算由 10 元替换为 3 元；允许这次在线评测，其他生产、支付、Nacos 和真实 `.env` 限制保留，不修改简历。

## 已实现的行为

### 评测与审核

`evaluation/run.py` 可通过 `--modes` 选择配置，按同题先基础 RAG、后完整 Agent 交错执行。`--review-source agent` 明确区分 Agent 编题/审核和正式独立人审；原正式人审仍要求至少 30 道非虚构题。`evaluation/review.py` 和 `report.py` 将 Agent 评分写入 `agent_metrics`，人工评分保留在 `manual_metrics`，不将 Verifier 的批准状态当成外部评分。

题集、原文依据及评分要点在 `evaluation/public_docs_v1/suite.json`。4 道事实、3 道复合、2 道部分可答、2 道缺证、1 道澄清。原始版本是 PostgreSQL `REL_17_6` 与 Celery `v5.5.3`，`originals/` 保留原文和许可证；`sources.json` 与 `corpus.json` 记录 URL、原始行号、转换及 SHA-256。实验只检索六份选定摘录，不能从缺证推断完整手册或现实中不存在答案。

审核逐条绑定最终 manifest 与逐题结果的内容哈希，要求核对全部引用关系、覆盖要点、适用条件、响应动作及禁用结论；失败和未执行题也保留，覆盖不能从失败草稿取得。没有独立人工审核，不产生独立人审成绩。正常业务 `ANSWER_REVIEW_REQUIRED` 默认值和发布审批接口均未放宽；仅隔离质量实验显式关闭。

### 总预算与调用

`evaluation/budget.py` 的持久化账本覆盖入库向量、查询向量、全部聊天角色调用。发送前按输入 UTF-8 字节加协议余量估计 Token、按输出上限预扣；预扣必须先落盘才允许 HTTP。累计或下一次最大预扣达到停止边界时停止新增调用，停止线 ¥2.5，保留 ¥0.5。未知价格、未登记端点/模型、未知用量及中断留下的未结算请求均阻止后续收费调用，不重试补分。

聊天使用用户批准的峰价输入 ¥2、输出 ¥8／百万 Token，不计缓存优惠。Embedding `Qwen/Qwen3-VL-Embedding-8B` 的官方价格页确认为 ¥0.7／百万 Token，原网页、截图及哈希在 `prices.json` 和同目录证据中。账本是按返回用量的费用估算，不是供应商账单或供应商侧消费限额；若供应商违背 Token 上限或费率约定，本机预估无法替代供应商侧控制。

专用脚本 `scripts/run_public_evaluation.py` 固定两组、一次、同快照、同模型、同索引，并在两个配置之间共用精确文本的内存向量缓存。完整 Agent 自己规划的新增查询仍可能需要新的向量；相同查询不重复收费。关闭 HTTP 自动重试，保留失败；同一输出目录存在 manifest 时拒绝重跑。通用 API 运行器没有这一本实验总账，不应绕过专用入口用于这次收费实验。

### Windows 启动与停止

原来 `data/processes.json` 只要存在就拒绝启动，即使所有 PID 都已退出。现在先核对 PID、Python 路径、创建时间和完整命令行；失效或复用为其他程序的记录归档，活跃或无法确认的项目进程阻止重复启动。启动/停止使用同一排他锁。

Windows 虚拟环境的 Python 可能作为启动器派生真实解释器。停止时在已核实的父进程仍活跃期间核对直接解释器子进程的父 PID、创建时间、路径和项目入口，再停止子进程及父进程。旧 PID-only 记录仍活跃但缺身份信息时不会自动强杀；此机制不声称能找回任意历史未记录的孤儿进程。

`-RuntimeDir` 和 `-Port` 将进程、日志、beat、初始化账号文件放到临时目录，不碰实际 `data/` 或 `.env`。`-Demo` 的 SQLite 文件也随该目录隔离。使用同一个 RuntimeDir 停止。

## 工程验收

- 集中后端回归：**417 passed、6 条既有 Alembic 配置弃用警告，151.31 秒**。测试包含原有真实 Docker 代码修复夹具，不调用付费模型。
- 前端：**23 passed**；TypeScript 检查和 Vite 构建通过。
- Ruff 全仓通过。新增预算、缓存、评分身份/哈希、两组交错和 PID 复用保护有控制测试；它们与全量重叠，不累加为额外成绩。
- 隔离 Compose 项目：`kbaccept-closure-20261114`，动态回环端口、独立 PostgreSQL/Milvus 卷及 Redis，不复用已有业务栈。质量实验在该 PostgreSQL 内再建临时数据库，退出时删掉仅由自身创建的数据库和索引。

浏览器使用系统 Microsoft Edge、1440×1000，加载生产构建；通过正常 `start.ps1` 启动 API、独立 Celery worker 和 beat，模型全部指向本机测试替身。这组流程证明产品交互与存储/队列协作，不用于评测答案质量。

已实际验证：旧记录恢复启动、重复启动阻挡、登录/建库、上传至索引就绪、创建共享阅读者、等待时不显示草稿、审批发布与逐字原文引用、沿用同一快照追问、取消无发布、断线恢复到同一运行且不重复创建、注入失败后显式新建运行重试、Agent 审核文案。完成后 API 端口关闭，测试 API/worker/beat 退出。

浏览器日志发现成员账号 HTML `pattern` 的连字符在现代 `v` 模式正则下非法，修为显式转义。只重建前端、定向补验该表单：空格无效、连字符有效并成功创建成员；没有重跑全部浏览器或模型组。修后无该正则错误。首次未登录 `/api/auth/me` 的 401 为预期身份探测；取消/终态关闭事件流产生的 `ERR_ABORTED` 为客户端关闭记录，不当作后端故障。

证据：`tmp/closure-3yuan/backend-regression.log`、`frontend-tests.log`、`frontend-build.log`、`frontend-member-fix-build.log`；浏览器目录中 `browser-report.json`、`startup-report.json`、`member-fix-report.json`、`startup-member-fix-report.json` 和截图。已逐张核对主要进度、引用、评测说明及修后成员表单截图。

## 边界与面试解释

BGE 本机冻结候选离线对照已完成，报告见 `evaluation/results/public-3yuan-v1-bge-offline-v2/report.json`：9 道有正例题的 Recall@3 为 1.000，BGE MRR 为 0.944，LLM 重排 MRR 为 1.000；q10/q11 无正例，q12 未调用重排。该结果不代表端到端答案质量。在线专用重排和角色路由没有做同题质量/成本对照：历史专用重排 smoke 缺少可核实 usage/账单记录，按预算规则没有继续收费请求。没有进行规模负载或所有文件格式的真实资料解析质量评测。

2026-11-15 补充：按角色输出上限和 q04/q05/q07/q08 定向续跑入口已实现，但四题实际收费重跑仍暂停，原因是账外 smoke 费用无法从当前项目记录核实。Docker Desktop 恢复后全后端 430 项通过，6 条为 Alembic 弃用警告。Agent 二次复核已完成，但正式独立人工评测仍为 pending，不能将其标为人审。

可以这样解释：“我把工程跑通和答案质量分开验收。工程用本机模型替身制造取消、断网和失败；质量用固定官方资料和同一题集对照，并给整次实验加持久化预算账。每笔请求发送前预扣，未知用量立即停；由 Agent 对照原文单独评分，保留失败，也保留正式人审与业务发布审批。”

可能追问：为什么不用 Verifier 的通过比例当准确率？因为 Verifier 是被测流程的一部分，不能代替另外阅读原文后的评分；Agent 审核仍缺少独立人工评审的外部独立性。
