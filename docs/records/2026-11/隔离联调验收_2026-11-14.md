# 2026-11-14 隔离联调验收

本轮不修改简历。用户明确允许启动本机 Docker，并使用独立临时数据库和卷联调；不修改真实 `.env`，不调用付费模型，不操作生产、Nacos 或支付服务。恢复契约仍为“答案不重复发布，恢复允许重新请求模型”。

## 结论与证据范围

真实 PostgreSQL、Redis、Milvus、独立 Celery worker/beat 和 PostgresSaver 的基本业务链路已跑通。真实浏览器也完成阅读者提问、待审正文隐藏、编辑者核对原文和审批、阅读者读取已发布答案及引用。不能再用此前 Docker 不可用来描述本轮结果。

模型推理使用 `backend/tests/conftest.py` 的确定性 `FakeProvider`，由验收入口在测试 worker 中替换；没有发送模型 HTTP 请求，也没有运行真实模型质量/成本对照。前期更新中的“本机测试服务”应准确理解为测试替身；本轮并未搭建模型 HTTP 服务。

测试材料仅为包含 dataset X、M、F1 82 的虚构 TXT。该证据说明运行流程和指定并发边界可用，不能证明真实问题准确率、复杂文档解析质量、负载性能或生产稳定性。

## 可复用入口与隔离方式

- `deploy/compose.acceptance.yaml`：独立 Compose 文件，以 `kbaccept-20261114` 项目名创建 PostgreSQL 17、Redis 7、Milvus 2.4.15；动态端口仅绑定 127.0.0.1，卷属于该项目。
- `scripts/acceptance/isolated_acceptance.py`：只接受 `kbaccept-` 前缀的项目名，查询该隔离栈端口，覆盖子进程环境，迁移隔离数据库；上传文件、beat 状态和日志使用临时目录。内部子进程模式要求测试父进程标记；代码仓库/工作区也指向临时目录。
- `scripts/acceptance/acceptance_concurrency.py`：在真实 PostgreSQL 上使用多个连接验证领取和发布边界；只由隔离入口调用。
- 可选 `--browser-port` / `--browser-stop` 启动独立本机 HTTP API，服务已有前端构建。触发停止文件或 15 分钟到期后清理自己启动的 API、worker、beat；它不是日常启动脚本。

本轮没有修改业务代码或恢复策略，仅新增验收 Compose、验收脚本和事实记录。数据库迁移运行至 `0011`。原有 `2-db-1`、`2-redis-1`、`2-milvus-1` 和 `project1-rag-qdrant-1` 不属于验收栈，不对它们执行停止或删除。

## 已实际验证

| 检查 | 执行方式与观察 | 限制 |
| --- | --- | --- |
| 上传到问答审批 | 登录、创建库/成员、TXT 上传；独立 Celery/beat 入库，真实 PostgreSQL FTS 和 Milvus 索引/检索；固定快照、幂等请求、问答待审、所见哈希审批、引用版本/SHA/文件内容、事件 after_seq 续读、单条答案 | API 自动验收使用 TestClient；另有下述真实浏览器操作 |
| PostgresSaver | 问答执行后检查对应 `run_id:attempt` 的 checkpoints 记录 | 恢复按新 attempt 从头执行，不能称从断点续跑或确定性重新生成 |
| worker 进程中断 | 在测试 Planner 暂停点终止独立 worker，确认 attempt 1；手动将该隔离任务租约设为过期，启动新 worker，观察 started 为 [1,2]、attempt 2 checkpoints、一个待审答案 | 租约过期由测试推进，没有等待真实 90 秒；允许重复模型调用，不能称模型 HTTP 恰好一次 |
| 并发领取与旧结果保护 | 8 个连接同时争抢同一个任务，仅一个返回 attempt 1；过期后再争抢，仅一个返回 attempt 2；旧执行不调用模型，旧 Workflow 发布抛 InterruptedRun，新执行仅写一个答案 | 控制场景，未做长时间压力或任意故障组合 |
| 撤权/版本停用与审核 | 一个事务删除提问者成员资格或停用来源版本，另一个连接尝试审核；通过 pg_stat_activity 观察实际 Lock 等待；前者提交后审批分别返回 404/409，无审批记录，原答案仍待审 | 覆盖“失效事务先持锁”的顺序，未穷举所有发布/撤权顺序或证明无死锁 |
| 并发版本与失败更新 | 同一文档的两个版本在 Embedding 阶段屏障会合，并发写入 PostgreSQL/Milvus；二者就绪后只有最新版本启用；第三次更新模拟 Embedding 失败，先前就绪版本仍启用 | 使用直接构造的隔离版本，模拟模型；没有跨数据库分布式事务保证 |
| 真实浏览器 | 127.0.0.1:18047，阅读者提问后待审正文隐藏；编辑者核对答案/原文并审批，回到队列；阅读者重新登录后查看已发布正文与原文；控制台无 error | 没有浏览器上传/共享创建、追问、断网重连、取消、失败重跑或 PDF 下载预览全覆盖 |
| 窄屏 | 390×844 下观察纵向布局，DOM 页面宽 375、viewport 390，无横向溢出；结束后恢复默认 viewport | 仅此视口和 TXT 页面，不代表所有移动设备 |
| 代码修复 Docker 回归 | `test_code_repair.py` 与 `test_part4_isolation.py`：16 passed（49.79 秒） | 临时夹具仓库与固定 Python 镜像，模型为替身；不代表多语言或真实缺陷修复率 |

## 命令与产物

```powershell
docker compose -p kbaccept-20261114 -f deploy/compose.acceptance.yaml up -d --wait --wait-timeout 180
.\.venv\Scripts\python.exe -X utf8 scripts/acceptance/isolated_acceptance.py --project kbaccept-20261114 --report tmp/isolated-acceptance-20261114/report.json
.\.venv\Scripts\python.exe -X utf8 scripts/acceptance/isolated_acceptance.py --project kbaccept-20261114 --versions-only --report tmp/isolated-acceptance-20261114/versions.json
.\.venv\Scripts\python.exe -m pytest backend/tests/test_code_repair.py backend/tests/test_part4_isolation.py -q --tb=short
.\.venv\Scripts\ruff.exe check scripts/acceptance/isolated_acceptance.py scripts/acceptance/acceptance_concurrency.py
```

`--versions-only` 在流程验收后、该栈所有测试 worker 停止时执行；脚本不负责创建/删除 Compose 栈。没有 Git 元数据，不初始化项目 Git。代码修复回归仅在临时夹具目录创建其所需的 Git 测试仓库。

证据目录 `tmp/isolated-acceptance-20261114/`：`report.json`、`flow.log`、`versions.json`、`browser.json`、`cleanup.json`、`browser-published.jpg`、`browser-mobile.jpg`。其中 browser/cleanup 为基于工具实际观察的人工整理记录，非自动化测试报告。截图是本轮临时测试账号和虚构材料；这些账号随隔离库删除，不是正式登录资料。警告为 pymilvus 2.4 使用 pkg_resources 的既有弃用提示。
