# 项目日志、共享配额和术语扩展默认接入（2026-11-17）

本轮用户明确要求把“项目日志 MCP、Redis 跨进程共享配额、术语/同义词扩展查询”加入现有问答。实现三项默认接入，不切换角色模型、不启用第三方工具或外部写操作、不修改真实 `.env`、简历和已有文档索引。

## 解决的问题

- 查询日志：文档能描述功能，但不能回答用户自己刚才哪次执行失败。开启内置只读日志工具，由 ToolRouter 判断是否需要调用；不是每个问题都直接读取日志。
- 共享配额：单个 worker 的预算挡不住多个 worker 合计超过账号的请求速率。所有真实模型 HTTP 尝试在发送前经过同一 Redis 窗口。
- 术语扩展：之前模块产生了扩展表达，但新 `facet_context` 路径首轮没有使用它们。本次把它们合并到实际候选召回。

## 实际行为与代码

`core/config.py` 默认开启 `WORKFLOW_MCP_ENABLED`、`PROJECT_LOGS_MCP_ENABLED`、`PROVIDER_QUOTA_ENABLED`、`QUERY_BUILTIN_TERMS_ENABLED`，查询扩展开关保持开启。通用 `MCP_ENABLED` 和 `MCP_WRITES_ENABLED` 仍关闭；未添加任何角色模型路由。`Settings` 的真实本机加载已确认这些默认生效，现有 `.env` 未设置对应覆盖值。

日志仍用 `agents/workflow_tools.py` 与 `integrations/project_logs_mcp.py` 的现有只读通道：actor、知识库和数据库由服务器注入，只返回本人、当前库的限定状态和调用信息。调用和回执哈希记录在本任务中，成功结果作为 `mcp_observation` 引用进入证据检查、核验及审核，失败工具结果不能作为证据。日志不读取其他用户的任务，也不直接推断故障根因。最多执行两次工具调用；选择工具本身消耗原有模型调用额度。

配额仍由 `integrations/provider_quota.py` 在 Provider HTTP 边界原子预留。相同 endpoint/credential 在不同模型、角色、进程间共用一个池；默认 **30 次 HTTP 尝试/分钟、200000 估算 Token/分钟**。额度是本项目应用策略，不代表供应商实际限额。Redis 不可用或配额不足时不发请求，失败/结果未知不退预留。本轮没有扩大任务自己的时间、Token、费用或调用次数预算。

`knowledge/query_rewrite.py` 新增 11 组保守的公共技术术语：PostgreSQL/Postgres、检索增强生成/RAG、模型上下文协议/MCP、倒数排名融合/RRF、向量嵌入/Embedding、消息队列/message queue、死信队列/DLQ、并发控制/concurrency control、多版本并发控制/MVCC、幂等性/idempotency、基于角色的访问控制/RBAC。这里是检索别名，不是答案事实，不自动发明公司内部简称或人物关系。

内置规则在创建任务时绑定到当前知识库；自定义 `QUERY_TERMS_FILE` 仍按文件中的 corpus_ids 过滤，规则内容随任务冻结。设置 `QUERY_BUILTIN_TERMS_ENABLED=false` 可只用自定义规则，`QUERY_REWRITE_ENABLED=false` 可关闭扩展。

`knowledge/facet_retrieval.py:expanded_rankings` 保留原问题，最多五个表达分别检索整块 BM25 与短窗口 BM25，各路线按表达交错合并后仍限制为前 100。向量只请求原问题一次；三路总候选最多 300，完整问题/最多两个子句统一一批 BGE，最终最多 12 个原文块。扩展不增加 Embedding 次数或 BGE 批数，但可能增加候选覆盖范围和词法计算。长于 500 字符的问题继续跳过扩展。审计事件保存实际使用的扩展表达，公共 SSE 只显示固定进度。

配置和准备方式见[开发与运维](../../guides/开发与运维.md)。重启 API/worker 后创建的新任务使用更新默认；旧任务保持自身冻结内容并受代码漂移检查保护。
