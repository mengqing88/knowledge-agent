q10、q11 为无正向标注的缺证题，三种方式均返回空上下文；其覆盖指标为不适用，未计为满分。q12 走澄清路径，没有重排记录，列为未重放。q04、q05、q07、q08 原答案状态仍为失败，本次只使用其已存的上下文，不将这些题改成答对或修复成功。

## 怎样保证对照可追溯

- [协议](../../../evaluation/context_selection_protocol.json)固定三种方式和判定规则；不以标准引文选择来源，不搜索参数、不追加实验组。
- 每题沿用已存的 8000 字符预算；总来源上限 32、单文档上限 16，排序、去重和预算规则一致。
- 核对题集、资料清单和原文哈希。当前方式重放出的 9 题来源顺序、标识、范围和正文均与已存 EvidenceGate 请求完全一致。
- q10、q11 的空上下文按已存的缺证短路分支核对。首次完整运行前的校验曾误要求这两题也存在模型 EvidenceGate 调用，已修正校验并加回归用例；未删题、未重试模型，也未调整选择策略。
- [原始报告](../../../evaluation/results/context-selection-v1/report.json)保存逐题选择范围、引文匹配、参考 Token、原失败状态及脚本/协议/输入 SHA-256；同目录保存协议副本。旧原始结果与资料未改动。

哈希对应本次 Windows 工作副本的原始字节，旧题集、资料清单和运行清单使用 CRLF 换行，而 Git 库内版本为 LF。跨平台检出时可能因换行转换无法直接通过旧哈希校验；本轮未重写冻结资料或旧哈希，不将字节变化当成原实验已复现。

执行入口为 [compare_context_selection.py](../../../scripts/evaluation/compare_context_selection.py)：

```powershell

.venv\Scripts\python.exe -X utf8 scripts/evaluation/compare_context_selection.py `
  --output evaluation/results/context-selection-v1
```

本次只有一轮完整的三方式离线对照；新模型请求 0 次、新增费用 ¥0。脚本的 7 项定向测试通过，Ruff 通过。未修改应用代码或产品默认策略，未重跑整栈。

## 结论能说明什么

这里的覆盖仅指：正确文档中的完整标注引文，经空白归一化后出现在某一个保留范围内。它不判定答案是否正确、所有适用条件是否齐全或是否存在幻觉。标签由 Agent 编写，本次也没有独立真人评分。

对照复用了同一次模型重排和块选择结果，没有重新检索或生成答案，因此不能证明取消块选择后的模型总成本、延迟或答案效果。只记录的本地组装耗时也不能用于声称端到端加速。

本样本资料短且数量少，未覆盖长文跨段依赖。补邻段只是有限扩展，不是重新建立小块索引、命中后返回父块的完整父子检索实验；MMR 和其他检索策略也未在本轮比较。当前证据支持继续使用块级筛选，后续若出现跨段条件丢失，应针对该类真实失败再评估扩展方式。
