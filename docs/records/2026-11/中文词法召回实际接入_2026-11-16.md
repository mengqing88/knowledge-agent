## 实现及运行方式

`backend/app/knowledge/lexical.py` 从前轮实验中复用完全相同的分词和 BM25 算法。它读取服务器提供的索引白名单，只构建本次快照的词法倒排表，不读其他知识库，不加载文档向量，不修改源文档或来源范围。

`retrieval.py` 在原有快照状态、Embedding 身份和索引配置校验之后，选择旧词法或新 BM25，继续沿用两路等权 RRF。没有修改现有文档分块、向量配置指纹或答案引用。切换词法实现不需要重新请求文档 Embedding 或重新入库。

词法索引缓存在单个 `Workflow` 对象中；缓存键绑定数据库 Engine、全部索引 ID 和容量参数。不同任务不共用缓存，每次使用前仍重新校验索引 ready 状态。构建和缓存命中都检查取消/执行状态，任务结束后释放对象。

`Settings`、`freeze_execution`、`ScopedTools` 和 `Workflow.retrieve` 串通三个新字段。排队期间全局配置改变，已有任务仍用创建时冻结的选择；旧清单中缺少这些字段时按 legacy 处理。应用源码哈希机制仍生效，代码改动前创建的未执行任务可能需要按现有机制重新创建。

| 配置 | 默认 | 用途 |
| --- | ---: | --- |
| `LEXICAL_BACKEND` | `legacy` | 可选 `ngram_bm25` |
| `LEXICAL_MAX_CHUNKS` | 5000 | 本次快照最多读入片段数 |
| `LEXICAL_MAX_CHARS` | 2000000 | 本次快照累计原文字符上限 |

超过上限会在查询 Embedding 前明确返回 `lexical_capacity` 错误；不悄悄截掉后半文档或伪称完整 BM25 召回。不在本轮增加大规模持久化词法索引。该上限约束读入文本规模，不能当成 Python 进程内存的硬上限；词法倒排对象仍占额外内存。

已有服务停止后，在同一 PowerShell 启动环境中设置下面变量，重启 API/worker/beat，才会对新任务生效。真实 `.env` 无需修改；配置样例已加入 `.env.example`：

```powershell
$env:LEXICAL_BACKEND = 'ngram_bm25'
scripts\start.ps1
```

回退时同样停止已有服务，设 `$env:LEXICAL_BACKEND = 'legacy'` 后重新启动；该选择只影响随后创建的新任务，不改冻结中的运行记录。不要在已有应用进程仍运行时重复启动。
