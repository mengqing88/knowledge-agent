# 独立人工试评准备记录

本轮只使用已保存的两组、同一套 12 题结果，准备可交给评审者的材料和回收入口。没有重跑模型，没有收费请求，没有填写真人评分，没有修改原题、原答案、原 Agent 判分或简历。

## 本次材料

- 资料：PostgreSQL 17.6、Celery 5.5.3 的六份冻结摘录，以及原始文件、版本来源和许可证。回答范围仍是六份摘录，附件中的完整手册不扩展可答范围。
- 题目：事实 4、复合 3、部分可答 2、缺证 2、澄清 1，共 12 题；原有题目和评分要点是 Agent 草案，先由真人核对。
- 答案：24 份记录全部保留，包含基础 RAG 的 3 份失败、完整 Agent 的 4 份失败。失败不以 trace 草稿补答，也不从统计分母删除。
- 匿名：按题随机排列 A/B，字母不固定对应配置。论点/证据 ID 改为 C1/E1；保留发布答案中的原话、条件、引用、缺口和澄清。隐藏配置名称、模型、运行元数据、Verifier 判断与 Agent 分数。
- 分离：评审者只接收 `reviewer.zip`；`operator-key.json` 留给操作者，用于恢复配置和原始 ID。映射及实际未填评分表放在被 Git 忽略的 `tmp/`，不上传公开仓库。

本次本地产物：`F:\项目2\tmp\independent-review-20261115\`。

| 文件 | 用途 |
| --- | --- |
| `reviewer.zip` | 可交给独立评审者的完整包；没有向任何人发送 |
| `reviewer/README.md` | 评分操作、范围和判据 |
| `reviewer/review-book.md` | 题目、待审核评分要点、逐字依据及 A/B 答案 |
| `reviewer/scorecard.json` | 空评分表，默认没有任何真人确认 |
| `reviewer/sources/` | 冻结摘录、来源元数据、原始文件和许可证 |
| `operator-key.json` | 本地保管的映射与哈希绑定；不要交给盲评者 |

原始结果已在公开仓库中，评审者主动查阅时可能推断映射；发布原话也可能透露流程特征。因此这里只称匿名试评材料，不声称实现了完全双盲。参与过生成、调参或原评分的人，不能仅凭填写布尔声明就变成独立评审者。

## 实际怎么评

评审者先读原文和题目，再确认评分草案是否正确、缺证范围是否明确。有歧义或错误，填写异议和依据，先保留原表，由实际评审者裁决；不能临时修改 gold 后继续汇总本版分数。

每份答案逐条判断引用是否支持整条论点、关系类型是否正确、条件是否偷换、必答点覆盖了哪些、有没有禁用结论，以及回答/部分回答/缺证/澄清动作是否合适。技术失败动作不能记正确；覆盖为零。无引用时不编造引用支持率。评分人填写理由、身份标识、带时区的时间，实际完成后才将该条 `independent_human_review` 改为 true。

只审一部分也可以回收，但该组未完整审完时总体质量率为 null。动作和条件的真人判断保存在导入后的逐题文件，现有人审汇总只统计引用支持、关系正确、必答点覆盖和禁用结论；不把 Agent 指标拼进人审成绩。不同人的评分应各自留存，分歧须由真实评审者对照原文处理，本工具不自动替人裁决。

## 导出、回收和完整性

入口是 `evaluation/blind_review.py`，使用标准库，不访问 API，也不影响答案发布、外部操作或代码补丁审批。

```powershell
# 输出目录必须不存在，避免覆盖任何评审工作。
.venv\Scripts\python.exe -X utf8 -m evaluation.blind_review export `
  evaluation/results/public-3yuan-v1 `
  --corpus evaluation/public_docs_v1 `
  --output tmp/independent-review-新的唯一目录

# 真人填写后，把表保存在包外，例如 tmp/returned-scorecard.json。
# 导入也须使用新目录；不会覆写原实验的 summary.json。
.venv\Scripts\python.exe -X utf8 -m evaluation.blind_review import `
  evaluation/results/public-3yuan-v1 `
  --key tmp/independent-review-20261115/operator-key.json `
  --scorecard tmp/returned-scorecard.json `
  --output tmp/human-review-新的唯一目录
```

导出先校验题集、语料清单、摘录和官方原件 SHA，且逐条确认评分引用确实位于摘录。导入校验源 manifest、每份结果（包括原来缺失的记录）、资料、阅读册和评分表身份，拒绝增删题目、改引用、重复条目、Agent 表冒充真人表、未确认评分草案、缺少签名/时间及给失败项计正确动作。

这些检查放在离线评测入口，是为了把评审者看到的材料与被统计的那一份答案绑定，避免用旧表给新答案计分。它们不能认证真人身份，或证明评审者遵守了独立性要求。

## 当前结论与边界

材料准备与回收工具已实现；真人判分仍为待审核。12 题即便全部真人评完，也只能报告这次小样本试评；项目规范的正式评测仍要求至少 30 道独立审核题和相应审阅证据。本次没有追加题目或预算，也没有将准备工作写成“正式独立人工评测已完成”。

面试可这样解释：“我把模型自己的核验和效果评分分开。给外部评审的是匿名答案、冻结原文和空表，保留失败题；回收时按哈希对应到原答案。程序检查表是否完整，但不把 Agent 填表当成人审。”

定向回归：`test_blind_review.py`、`test_human_evaluation.py`、`test_lean_evaluation.py` 合计 **58 passed in 7.55s**，改动代码 Ruff 通过。覆盖匿名标识/自评隐藏、每题独立排列、失败与缺失分母、源材料/答案变更使评分失效、真人声明/时间/评分异议校验，以及部分审核不产出总体率。

实际导出了上述本地包（14 个文件，ZIP 60,500 字节），核对为 17 份 completed、7 份 failed，评分表 24 项真人声明全部 false；ZIP 不含映射、模式名、Verifier 字段和 Agent 分数。实际用空表执行导入，单独输出 `pending-check/`，两组均为 0/12 已审、质量率 null。该检查只证明入口保持待审，不是真人评测，也没有修改原实验汇总。
