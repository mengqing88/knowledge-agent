## 改动与理由

原来后端应用文件、工具脚本与技术文档分别堆在同一层，README 和 TODO 混入多轮历史验收，日常操作需要从大量旧记录中找入口。现在后端为 `api/core/knowledge/agents/integrations/jobs/repair` 七个职责目录；前端为 `components/api/features/runs/types/styles`；脚本分为 `benchmarks/acceptance/smoke/evaluation/models/demo`。

`start.ps1`、`stop.ps1`、`manage.py`、`agent_profile.py` 和 `process-state.ps1` 仍在原处。ASGI 与内部 Celery/MCP Python 模块路径随代码调整，对外 HTTP 路由、数据库迁移编号、Celery 任务名、权限和审批逻辑不变。维护者直接导入内部模块时须使用下方新路径。

配置文件的项目根定位随目录深度调整；执行清单改为递归记录后端源码哈希，避免分包后遗漏实际工作流。常规实验和冒烟的新报告默认落到 Git 忽略的 `tmp/reports/`，历史 JSON 归入 `docs/records/benchmarks/` 并保持字节不变。

README、TODO、评测导航的原累计说明分别保存在历史资料目录。当前架构文档修正了旧的“无注册”描述；本机注册已有实现，不代表公开部署或自动加入他人知识库。

## 保留与边界

没有删除已有文件、业务容器、Docker 卷、数据库或模型。真实 `.env`、本地 `data/`、`tmp/` 和依赖位置保留；中断的 BGE v1 本地目录仅补充 Git 忽略项，未删除或移动。原问答评测目录与题集不改内容；历史报告里的旧路径和哈希继续表示当时执行版本，不把旧结果改成新版本验证。

`项目档案_供简历Agent使用.md` 按用户要求保持原文，因此其中历史路径未逐条改写；需要查代码时用本表。`项目共享说明.md` 继续留在根目录保留协作约定，并补充本次事实。正式人工评测、在线质量对照等任务不因目录整理而变成已完成。

本轮不发送模型请求，不执行生产、Nacos 或支付操作。整理前哈希与搬移清单在本机 `tmp/project-organization-20261115/`；这些本地检查产物不上传。
