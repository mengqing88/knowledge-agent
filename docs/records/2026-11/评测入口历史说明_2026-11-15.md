自动汇总的分母：技术失败率=失败题/全部题；`correct_refusal_rate` 是正常完成且返回不足状态的题数/标记为无答案的题数，`false_refusal_rate` 是正常完成却返回不足状态的题数/标记为可回答的题数。两者都是状态代理指标，不能证明答案内容正确或题集标签已获人工审核。动作匹配只计有效预期标签，并报告有标签的题数；不能当成答案质量。没有引用时引用支持率不适用；空答案和缺引用论点单列。每题的技术失败仍保留在全部题数中。

`--snapshot-id` 只允许虚构开发题重新绑定，不修改原题文件；正式题仍固定其原始快照。运行会调用实际模型；本次代码改进只完成离线回归，没有声称已跑完这 12 题的真实模型比较。不要在正常业务知识库关闭人审。

人工标注逐题绑定 manifest 和结果文件 SHA-256；修改结果后旧标注失效。填写审核者、`independent_human_review: true`、每条引用关系的真假判定、`covered_required_keys` 和禁用结论检查。模板默认全部待审，不自动确认人工身份。全模式均导出，允许先完成某个模式；该模式未完整审完时总体质量率保持 null。缺失/失败/取消题也保留；其覆盖要点只能为空，不能从分母删除。无 supports 引用时语义支持率为 null。

如要统计探索性 Hit@5，可在冻结问题里添加由人工标注、对应当前快照的 `relevant_chunk_ids`。固定口径为每道有标签题的首 attempt、首轮、第一条检索请求的前五名；分母包含全部有标签题，缺失运行/检索计未命中并报告 `top5_missing_queries`。不合并多个子查询的前五名，也不让补检或恢复增加分母；这只是首查询 Hit@5，不是子问题级 gold 或 Recall@5。全部缺少标注时分母为零且指标为 null。延迟报告给出有实际耗时记录的 P50/P95/max；费用只有全部运行 usage、价格来源与同一币种均明确时才汇总，否则为 null。

汇总以 manifest 中全部题为分母：缺失文件也计为技术失败，重复/未知题号直接报错，非终态不能计为完成。取消单列且保留在总题数中。P95 使用有实际耗时记录的全部尝试（包含失败/取消），采用最近秩 `ceil(0.95*n)`，同时报告观测数。未知 Token 调用不相加为零；已知 Token 小计另列，`token_totals_complete=false` 表明不能拿它充当总账。缺失调用列表计入 `missing_call_traces`，无效或缺失用量计入未知调用。各 run 的价格估算来自 `trace.accounting`；汇总输出币种和价格来源清单，混币种或任何用量/价格未知时费用为 null，没有供应商账单对账能力。


评测账目补充（2026-11-14）：仅当记录显示任务 completed 且无技术错误时，才把最终用量视为已观察到；运行中、超时或取消（包括已返回取消回执）计入 unconfirmed_final_usage_runs，已知 Token 仍保留为小计，但 token_totals_complete 为 false、总估算费用为 null。取消回执不能证明外部请求已结束；completed 仅反映当前存储记录，不能证明供应商账单结清或外部调用绝无在途。新增 4 个反例修复前失败；评测相关四个测试文件 47 passed（5.01 秒），Ruff 通过，未调用模型或网络。真实材料、独立人审与真实模型效果对照仍待完成。
