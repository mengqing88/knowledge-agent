# 新选择策略接入实际问答（2026-11-17）

用户明确要求“新选择策略接入”，随后确认用“新问答默认启用新策略”替换此前“默认不变”。本次只调整问答检索与选择及其配套配置、进度和说明；真实 `.env`、简历、已有文档及索引不改，不新增收费请求。

## 原问题与接入位置

此前 95.35% 只来自离线实验：工作流仍调用旧混合检索并交给聊天 Reranker 筛块，网页没有使用实验选择结果。因此仅新增实验入口或切换词法后端，都不能把整套策略带进真实问答。

现在 `Workflow.retrieve` 依据本次冻结的 `retrieval_strategy` 分支。新建完整 Agent 问答默认 `facet_context`，`baseline_rag` 保留旧对照，显式 `RETRIEVAL_STRATEGY=legacy` 可回退。旧任务缺少该字段时按 legacy 分支，已有代码/环境漂移校验仍可能要求新建任务，不会静默迁移旧任务。

## 实际流程

1. 先验证本地环境、模型哈希与快照的版本、模型和维度，再读取有界文本；缺失配置、无效来源或超出容量在收费 Embedding 前失败。
2. 整块 BM25、约 160 字符短窗口 BM25、Milvus 向量各取最多 100 条，按名次交错合并去重，最多 300 个候选。向量只请求一次，SQL 只读文本与来源，生产向量仍来自 Milvus。
3. 在独立 Python 环境运行本地 BGE；完整问题与最多两个语法子句共用同一候选池，最多 900 对。子句不额外请求 Embedding，不调用聊天重排器或在线 rerank。
4. 完整问题前五命中及后邻块优先；新增子句首选命中补前邻块，再有限向后补充。最多 12 个原文块，邻块占用正常结果名额，不能跨索引。完全重复文本可折叠为更少结果。
5. 从已验证 SourceBlock 的原文范围生成引用，继续执行 EvidenceGate、Analyst、Verifier 和既有审核门禁。上下文字符、来源数量限制仍生效，进入最终答案的证据可能少于选择结果。

首次检索保留原问题的语法边界；追问采用 Planner 消解指代的问题。首轮不逐条执行 Planner 的改写表达，避免同一问题反复加载模型；证据门控仍可提供有限补检查询。补检仍受既有执行去重、轮数和总预算约束。

## 代码、进度与代价

- `backend/app/knowledge/context_selection.py`：实验与实际工作流共用的宽召回、来源顺序和选择算法；`evaluation/context_recall.py` 保留旧导入兼容。
- `facet_retrieval.py`：快照校验、容量约束、Milvus 前 100、来源验证与最终选择。BM25/来源索引缓存在本次 Workflow 内，不跨用户或任务共用。
- `local_reranker.py`：独立解释器与固定模型文件验证，核对问题/候选/模型的哈希，拒绝漏分、外来 ID、重复 ID 和非有限分数。推理时禁止联网补模型，缺失时明确失败，不静默降级为另一条收费路径。
- `governance.py`：任务冻结策略、本地路径/设备/时限、模型清单与推理脚本哈希。已有应用代码身份覆盖新共享模块。
- `workflow.py`、`tools.py`：实际接入并保留引用/预算/权限校验。进度显示“正在筛选证据”，完整审计事件保存候选路线、选择 ID、模型身份、推理对数与耗时；公开进度不含正文、候选或模型输出。

模型文件约 2.3 GB，另需独立推理依赖。本次复用已有环境，未下载安装。默认设备 auto，独立推理上限 120 秒，同时受任务总时间限制；取消或失去 attempt 后终止子进程，Windows 包括其启动的解释器。每次检索启动新进程并加载模型，没有新增常驻模型服务，因此有加载开销；CPU 可能在代表性候选量下达到时限。准备及回退命令见[开发与运维](../../guides/开发与运维.md#本地-bge-检索)。

## 结果边界与复述

代码已经接入真实问答路径并改为新建完整 Agent 问答的默认；重启 API/worker 后新建问题生效。本次没有启动或替换用户正在运行的应用服务，也没有复跑私有 17 题或在线付费模型。

历史 **41/43（95.35%）** 仍然是反复查看同题后得到的离线开发覆盖；共享代码和单条冒烟通过不能证明真实资料上仍有 95%，也不能代表答案准确率、独立泛化或容量/延迟达标。

面试可复述：“我把离线选择算法迁入实际工作流，三路先扩候选，再用本地 BGE 分别看完整问题和子句，最后在固定名额内补原文上下文。它复用既有快照、原文引用和审核门禁；我验证了真实存储与本地模型能跑通，但同题离线覆盖和线上问答质量分别报告。”

可能追问：为什么不再交给聊天重排器筛一次？因为它可能再次删除为多子句保留的证据，而且增加在线调用；最终是否足够支持结论仍交由后续证据检查与核验处理。
