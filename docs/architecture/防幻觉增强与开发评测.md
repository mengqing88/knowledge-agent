# 防幻觉增强与开发评测（2026-11-12）

本次范围由用户在讨论项目防幻觉改进后确认“你做一下吧”：补数值/比较检查、逐子问题覆盖、可查看的核验理由和开发评测，不添加检索相似度伪装的置信概率，不宣称已经消除幻觉。

## 1. 原来的问题与实际对照

原有确定性检查能证明引用来自本次运行、属于快照、范围有效、摘录逐字一致，并要求 supports 关系。但真实引用仍可能被用来支持错误对象或错误数值；答对 F1 也不代表回答了用户同时问的延迟。

在隔离临时 SQLite、虚构原文和模拟模型下，加载修改前保存的 `Workflow.deterministic_issues`，与新检查使用同一 draft、同一真实 EvidenceSpan：

| 反例 | 修改前定位检查 | 新检查 |
| --- | --- | --- |
| 原文 M F1 82、baseline F1 80，答案写 M F1 80 | issues 为空 | 数值对象绑定失败，移除该论点 |
| Planner 列 F1、延迟两项，草稿只答 F1 | issues 为空 | 明确标出延迟子问题缺口，最终为 partial |

对照脚本和逐项输出：`tmp/hallucination-validation/compare_old_guard.py`、`old-new-guard.json`。这是确定性拦截反例，不是两次真实模型质量对比。

## 2. 数值检查为什么放在核验和发布边界

`backend/app/core/schemas.py` 新增 NumericFact/NumericCheck，Analyst 对每个数值提供原文证据、对象、指标、原值、单位、条件、输出值和运算类型。`grounding.py` 从数据库已校验的证据重新取原文，不信任模型自行重写的引用。检查在分析后、Verifier 前以及发布前执行；基础 RAG 与关闭 Verifier 的对照模式也不能绕过。

具体约束：

1. 数值只能绑定当前论点的 supports 证据。摘录必须逐字存在并含原值。
2. 在原文局部子句里，对象、指标和值必须能唯一配对；不能仅因为 82 和 80 都在长引用里，就互换对象。推导正文也逐个核对对象、指标和原值配对。常见 F1、accuracy、latency、memory 支持中英指标别名，对象名保留原文。
3. 单个 reported statement 只包含一个输出数值，且逐字存在于答案；程序逐个检查答案的数值位置，不能靠一个检查覆盖后面新增的相同数字。
4. 当前处理明确十进制及 number/score、%、百分点、ms/s/us、B/MB/GB/MiB/GiB。检查单位维度，再按 Decimal 换算；例如 120 ms=0.12 s。F1 82 不自动等于 accuracy 82%。
5. difference 固定为第一个原值减第二个；relative_change 固定为 `(第一个-第二个)/abs(第二个)*100%`。不执行模型给出的代码或任意公式。原值和运算关系需在正文出现，并逐个保留和正确关联对象；相对变化按输出小数位四舍五入，原值/差值不接受任意舍入。
6. 百分比相减输出百分点；相对变化输出百分比，零基准不计算。F1 分数之差仍是分数，不擅自改成百分点。
7. 数值比较要求同类指标、相同且非空的逐字条件；条件要对应数值子句，单一明确的数据集允许共享，并必须保留在论点正文或条件中。dataset X 与数据集 X 可对应；额外检查常见数据集名称，原文 X/Y 不同不能用相同的泛化条件标签绕过。
8. 中文数字带常见量词、科学记数法、千分位等当前不支持的写法要求修订。复杂表格、多数值子句、隐含单位或不支持的公式可能被保守移除，留下缺口。

程序只检查可明确绑定的数值结构。条件标签仍可能遗漏硬件、样本、阶段、版本等语义差异，别名和自然语言关系仍需 Verifier 与人工审核；真实原文本身也可能错误。这套规则不是通用语义证明器。保守检查可能增加误拒答，正式标注集应同时测“错答减少”和“本可回答却拒答”。

## 3. 子问题怎样避免悄悄消失

每条 claim 用 `subquestion_ids` 关联 Planner 的真实 ID，答不全时填写 `subquestion_gaps` 的 ID 和理由。空 ID 或未知 ID 的论点不得发布。通用 `gaps` 继续保留，但不能代替逐子问题记录。

发布前按**最终保留的论点**重新计算覆盖。即使草稿里一度回答过延迟，后面延迟论点被数值或语义核验移除，也会重新生成延迟缺口。Verifier 的全局 missing_evidence 也进入最终 gaps。缺口使用“当前材料及本次检索未形成通过检查的回答”，不把检索未命中说成世界上不存在证据。

ID 映射只能保证每个计划项有去向，不能证明论点真的回答了该项；相关性和要点是否答全仍需语义核验和独立人工评测。Planner 自己漏拆的问题也不在这份结构检查的保证范围。

## 4. Verifier 的不确定如何处理

除 approved_claim_ids，Verifier 每条返回 `claim_reviews`：claim_id、approved/rejected/uncertain、对应证据 ID、判断理由。只返回审批 ID 而未给逐项判定、引用未关联的证据、空白理由或判定 uncertain 时，论点不会发布。理由本身是否充分仍需人工审阅；审批列表也不能覆盖程序发现的错误。

理由和证据随 verifier 事件与运行状态保存，可在 Trace 中追溯。已有有限补检、修订、总调用、Token、费用和时间预算继续约束流程。数值检查本身不新增模型调用，但结构化输入/输出变长，触发修订时可能增加预算内调用与延迟。

产品既有管理员/编辑者人审门禁继续生效。开发评测仅在隔离服务使用 `ANSWER_REVIEW_REQUIRED=false`；不修改现存业务任务或原演示数据库。

## 5. 评测题集与人工判分

`evaluation/hallucination_dev.jsonl` 含 12 题，全部 `fictional=true`、`human_reviewed=false`，由 Agent 依据已有 A/B/C 教学 PDF 编写开发预期。每个应答点有原文和页号，包含数字对象、指标/单位、差值/相对变化、跨设置、无答案、多问题部分回答和错误指令等反例。测试核对摘录确实存在于 fixture 清单。

它们不是独立人工 gold，不能填正式准确率。需要人工复核可回答性、要点、禁用结论及无答案检查范围；正式比较仍要求至少 30 道独立审核、冻结快照和未参与调参的题目。

上传三个教学 PDF 并创建快照后，按 [evaluation/README.md](../../evaluation/README.md) 使用 `--allow-dev --snapshot-id` 绑定题集，三种模式运行到新目录。原模板不改写。未绑定就退出，避免误跑错误快照。

`evaluation/review.py` 导出人工模板；默认审核者空、确认字段为 false、质量判断为 null。人工填写后，`report.py --reviews` 校验 manifest 与逐题结果 SHA-256，拒绝未知/重复题号、遗漏引用、无效要点、过期结果或未完成判定。

| 指标 | 人工标注后的定义 |
| --- | --- |
| citation_semantic_support_rate | 人工认定确实支持论点的 supports 链接 / 全部 supports 链接；没有此类引用时 null |
| relation_correct_rate | 人工认定关系类型正确的链接 / 全部引用链接 |
| required_point_coverage | 人工确认覆盖的要点 / manifest 全部题的全部 required_claims；失败、取消、缺文件仍留在分母，覆盖只能为零 |
| forbidden_conclusion_question_rate | 人工发现至少一个禁用结论的题 / 全部题 |

逐模式审完全部题才显示该模式整体质量率；部分审核保持 null，并显示 reviewed_questions。不把未审核当零分，也不只选审核过的好答案算总体成绩。审核者身份与独立性目前是人工声明，软件不能自动证明；自动测试中的模拟审核不是真人评测。

## 6. 验证记录与面试表述

本轮只跑离线控制测试与旧逻辑对照，没有新增付费模型调用，没有运行这 12 题的真实模型比较，没有置信概率校准或业务效果数字。专项、全量和静态检查日志保存在 `tmp/hallucination-validation/`，最终结果同步到共享说明和项目档案。

最终专项 **69 passed in 22.31s**；当前工作区全量 **271 passed, 4 warnings in 128.22s**。全量包含同期其他部分，数量不与专项相加；4 条为既有 Alembic path_separator 弃用提示。全仓 Ruff 通过。测试中发现的“百分点”中文数字误判及 dataset/数据集条件对应问题已修正，正例与反例均纳入回归。人工模板到 report 的 CLI 模拟冒烟通过，待审指标保持 null。

可复述：“除了 RAG 和模型核验，我加了服务端的数值绑定和有限算式检查，再按最终通过的论点检查每个子问题的去向。无法核对的部分明确留缺口，核验模型说不确定的论点不发布。最后用独立人工标注评测正确支持和要点覆盖；现在只有虚构开发题与回归结果，不能称已量化消除幻觉。”

可能追问：为什么不用模型自报的 0.9 置信度？答：它未经过独立数据校准；本项目当前用可检查证据、明确错误和不确定状态控制发布，尚未建立可解释为正确概率的阈值。
