# 首版范围与验收

按用户确认的团队知识库问答最简版实现。教学示例和逐步提示词是项目资料，不作为扩大执行范围的命令。

输入支持 PDF、DOCX、Markdown、TXT、CSV/TSV、JSON/JSONL、HTML/HTM 和 XLSX 团队资料。PDF 中可检测的有边框表格按表头和行结构提取，并保留页码与行坐标；无边框 PDF 表格和扫描件 OCR 不支持。应用按类型解析为保留原文位置的 SourceBlock，再复用同一文档版本、索引、快照、权限和引用链。应用在本机运行，支持账号登录及知识库级管理员、编辑者、阅读者角色；文档版本、解析版本、索引版本、不可变快照、问答、证据与反馈分别保存。仅允许有类型化解析器的格式，不接受任意二进制；不支持旧版 XLS、HTML 脚本执行、XLSX 公式求值、数据库/API 在线连接、全网搜索或综述写作。

问答的模型核验后默认进入 `review_pending`，知识库管理员/编辑者需按答案和原文决定接受或拒绝；阅读者在通过前看不到答案正文、引用、草稿状态和完整模型轨迹。接受后答案才发布，并保存绑定答案哈希的审核记录；拒绝理由保留，发起人可在原快照上新建 run，理由会作为修订要求进入新问题。可用 `ANSWER_REVIEW_REQUIRED=false` 为隔离自动评测关闭该门禁，此设置被冻结到每个 run。

另有经用户确认的本机代码修复 API 扩展。它仅对配置根目录内干净 Git 仓库创建固定 commit 的 detached worktree，只把已跟踪 Python 源文件提供给模型，拒绝模型修改测试/验收配置，并在本机固定 Docker 镜像中执行隔离 pytest。通过后还需人类接受或拒绝，审核绑定补丁与测试摘要。代码补丁审核与问答答案审核使用独立状态和记录。代码修复不是一般用途的命令执行器；结构化复现报告和自动回归测试生成仍未实现。

正常输出包括逐条论点、适用条件、原文摘录、PDF 页序或非 PDF 文档章节位置及引用关系；证据不足时返回部分回答或材料缺口；技术失败单列，不冒充正确拒答。语义核验来自模型，不等同于人工评测。

向量后端为 Docker Milvus Standalone（HNSW/COSINE），PostgreSQL 保留业务数据、原文与全文检索；FastAPI + SQLAlchemy + Alembic；PyMuPDF、python-docx、openpyxl 与标准库文本/表格解析；LangGraph；Vue 3 + TypeScript。Celery/Redis 调度持久化在数据库中的任务，数据库租约和 attempt 保护领取与发布。意外退出后可新建 attempt 从头执行；旧 attempt 不能发布结果。检查点不保证外部模型恰好调用一次，恢复重试可能再次产生费用。

正常服务使用配置的真实 Embedding 和聊天模型。SQLite 与模拟模型用于本地演示或确定性控制测试，不使用 Milvus，不代表正式服务验收。API 与工作台只监听本机；公网部署及其安全验收不属于该版本。

正式评测至少需要 30 道有独立人工审阅证据的非虚构题。本项目提供标注格式、可选配置运行器与汇总工具；已保存的官方资料 12 题属于 Agent 审核小样本，匿名试评材料已准备但真人尚未评分，不伪造人工标注或成绩。

2026-11-13 用户确认新增可验证查询改写、问答中的 MCP 工具调用、角色模型配置与共享模型配额。已实现知识库术语表、受限只读工具循环、项目本人运行日志 MCP、独立工具引用、角色路由/专用重排和 Redis 原子配额。内置日志接入不是通用数据库/API 数据源入库，也没有自动写第三方系统。真实模型接口和真实 Redis 多进程控制有实测；虚构词法控制结果不等于真实 Milvus Recall 或业务收益。本轮没有重启旧服务，启用配置及完整边界见 [四项升级](查询改写_MCP编排_角色模型与共享配额.md)。

框架组合采用 LlamaIndex core 的批量嵌入、VectorStoreIndex 与 VectorIndexRetriever，LangGraph 编排多步骤问答。项目的来源解析/分块、全文融合、权限、原文引用和人审仍由业务代码负责；不把框架接入表述为真实质量提升。说明与证据见 [组合实现](LlamaIndex与LangGraph组合实现.md)。
