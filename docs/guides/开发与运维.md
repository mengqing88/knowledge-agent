# 开发与运维

日常使用见[启动与日常使用](启动与日常使用.md)，代码职责见[后端](../../backend/README.md)、[前端](../../frontend/README.md)。命令均从项目根执行。

## 配置

聊天字段：`CHAT_API_KEY`、`CHAT_BASE_URL`、`MODEL`、`CHAT_API_STYLE`。默认协议为 Responses；兼容 Chat Completions 时设置 `CHAT_API_STYLE=chat_completions`。

向量字段：`EMBEDDING_API_KEY`、`EMBEDDING_BASE_URL`、`EMBEDDING_MODEL`、`EMBEDDING_DIMENSIONS`、`EMBEDDING_REVISION`。维度 0 允许入库时发现维度，此后查询强制校验；更换模型、服务、维度或权重版本后须重新建索引和快照，旧快照不覆盖。

字段定义在 `backend/app/core/config.py`，环境示例在根目录 `.env.example`。真实 `.env`、模型密钥和会话令牌不提交、不写进问题或报告。

词法检索默认 `LEXICAL_BACKEND=legacy`；可在启动环境中显式选择 `ngram_bm25`，不需重建向量。新方案每次工作流只在当前快照内构建有容量限制的 BM25，默认最多 5,000 片段/200 万原文字符，超限明确失败而不截断。选择和容量固定在新任务的执行清单中，重启全局配置不改变旧任务。仍有退步题和规模限制，实际验证与切换/回退方式见[中文词法接入](../records/2026-11/中文词法召回实际接入_2026-11-16.md)。

## 手动启动与开发

正常存储为 PostgreSQL + Milvus，Redis 是 Celery broker。仅启动 API 无法处理异步任务。

```powershell
docker compose up -d --wait db redis milvus
.venv\Scripts\python.exe -X utf8 scripts\manage.py migrate
.venv\Scripts\python.exe -X utf8 scripts\manage.py migrate-vectors
.venv\Scripts\python.exe -X utf8 scripts\manage.py init-admin
```

另开三个终端，分别运行：

```powershell
.venv\Scripts\python.exe -X utf8 scripts\manage.py api
.venv\Scripts\python.exe -X utf8 scripts\manage.py celery
.venv\Scripts\python.exe -X utf8 scripts\manage.py beat
```

入口内部使用 `app.api.main:app` 和 `app.jobs.tasks.celery_app`；根目录启动/停止命令保持不变。Windows 中文路径统一通过 `manage.py` 配置 Python 搜索路径，不依赖 editable install 的 `.pth` 编码。

前端从 `frontend/` 运行 `npm.cmd run dev`；`npm.cmd run build` 产物在 `frontend/dist/`，后端启动时发现构建后提供静态工作台。

## 进程与隔离运行

脚本以隐藏窗口启动 API、worker、beat。进程记录绑定 PID、创建时间、解释器和命令行，核对失效记录后归档；身份无法确认时阻止重复启动，不自动强杀。`start.ps1` / `stop.ps1` 共用排他锁。

显式演示模式 `scripts\start.ps1 -Demo` 使用 SQLite 与 SQLAlchemy broker，不使用 Milvus，也不证明正式存储或模型质量。服务仍使用当前配置的模型，演示不意味着模型调用免费。

隔离环境通过进程环境变量指向临时依赖，使用 `scripts\start.ps1 -SkipDatabase -RuntimeDir 临时目录 -Port 18082`。停止时传同一 RuntimeDir。该目录承载账号文件、日志、进程和 beat 状态；无需修改真实 `.env`。已有独立 Compose 示例为 `deploy/compose.acceptance.yaml`。

## API 操作顺序

Swagger 在 [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)。先注册或登录，保留会话 Cookie，再操作本人有权访问的知识库。

| 步骤 | API |
| --- | --- |
| 建库 | `POST /api/corpora`，`{"name":"团队知识库"}` |
| 上传 | `POST /api/corpora/{id}/papers`，multipart `file`；更新同一文档传 `paper_id` |
| 等待入库 | 查询版本至 ready；失败通过 `/api/paper-versions/{id}/retry` 显式重试 |
| 固定资料 | `POST /api/corpora/{id}/snapshots`，`{"paper_version_ids":["实际版本ID"]}` |
| 问答 | `POST /api/question-runs`，附 8–128 字符 `Idempotency-Key`，正文含 snapshot_id、question、mode |
| 进度 | `/api/question-runs/{id}/events`；`after_seq` / `Last-Event-ID` 续读 |
| 发布审批 | `POST /api/answers/{id}/approval`，发送所见 answer_sha256、accept/reject，拒绝附 reason |
| 追问 | 新请求附 parent_run_id，沿用同一 snapshot |
| 反馈 | `/api/answers/{id}/reviews`，反馈不成为文档事实 |

审批内容哈希来自展示时读取的答案，不在冲突后自动取新哈希重试。正常产品默认 `review_pending`，管理员/编辑者审核发布前阅读者不能读正文。个人事件/trace 限本人，不因共享答案而开放。

证据状态与技术状态分开：supported/partial/conflicted/insufficient/needs_clarification 不等于失败状态。取消不能撤回外部在途请求，恢复新 attempt 可能再次请求模型；保证答案不重复发布，不保证模型恰好调用一次。

## 教学、检查与评测

`fixtures/` 中 PDF 和控制题是醒目标记的虚构教学资料，不能当作正式业务结果。导入入口：

```powershell
.venv\Scripts\python.exe -X utf8 scripts\demo\load_teaching_demo.py --username admin
```

密码隐藏输入，或用 `KB_EVALUATION_TOKEN` 环境令牌；不要把密码放命令行。入库仍会使用真实 Embedding。真实连通性检查 `scripts/manage.py doctor --output tmp/reports/connection-check.json` 也会调用模型，当前未知账外费用未核实前不执行。

工程回归与构建：

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\ruff.exe check backend evaluation scripts fixtures
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
```

代码修复部分测试需要本机 Docker 与固定沙箱镜像。真实 PostgreSQL/Milvus/队列联调、模拟模型控制、在线质量比较是三种证据；不能互相替代。具体结果与费用边界见[评测导航](../../evaluation/README.md)和[当前待办](../../TODO.md)。
