# 启动与日常使用

命令从项目根目录执行。本机目录是 `F:\项目2`，新克隆位置可自行选择。

## 首次准备

需要 Python 3.11–3.13、uv、Node.js 和 Docker Desktop（Linux containers）。Python 与前端依赖分别由 `uv.lock`、`frontend/package-lock.json` 固定。

```powershell
uv sync --frozen
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
```

新环境根据根目录 `.env.example` 创建本机 `.env`，填写聊天和 Embedding 服务。已有 `.env` 保留。模型密钥只供后端使用，不提交到 GitHub。配置字段见[开发与运维](开发与运维.md)。

## 启动与停止

```powershell
scripts\start.ps1
```

启动脚本准备 PostgreSQL、Redis、Milvus，执行迁移与旧向量回填、初始化管理员，然后启动 API、Celery worker、beat。成功后打开 [http://127.0.0.1:8000/](http://127.0.0.1:8000/)。前端须先构建；开发模式也可单独在 `frontend/` 运行 `npm.cmd run dev`，打开 [http://127.0.0.1:5174/](http://127.0.0.1:5174/)。

```powershell
scripts\stop.ps1
```

停止脚本核对项目进程身份后停止 API/worker/beat。日志与进程记录在 `data/`，该命令不删除数据库或 Docker 卷。

## 账号、上传与问答

1. 使用 `data/admin-login.txt` 中本机初始化账号，或在登录页选择“没有账号？注册新账号”。密码为 8–128 位；账号支持字母、数字、下划线、点和连字符，最多 80 字符。
2. 创建知识库，或由现有知识库管理员共享给你的账号。
3. 管理员/编辑者在材料区上传文档，等待处理状态变为“可用”。支持 PDF、DOCX、Markdown、TXT、CSV/TSV、JSON/JSONL、HTML/HTM、XLSX。
4. 选择材料并提问。等待期间展示处理进度，正文在检查完成后显示；正常配置还需管理员/编辑者审核，阅读者在发布前看不到正文。
5. 发布后点开引用核对原文、查看运行记录，或沿用同一资料快照追问。

同库成员的个人运行记录保持隔离；公开注册本机账号不等于自动加入其他人的知识库。扫描件 OCR、无边框 PDF 表格恢复、全网搜索和公网多租户部署不在当前范围。

进程冲突、模型配置、隔离运行和 API 用法见[开发与运维](开发与运维.md)。
