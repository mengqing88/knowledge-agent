# 多格式数据解析实现记录

更新日期：2026-11-13。本项目用于面试准备；本记录说明多格式入库实际实现、设计理由、验证范围和不能夸大的边界。

## 目标与范围

用户将输入从 PDF、Word 和 Markdown 扩展到常见数据文件。当前支持 PDF、DOCX、Markdown、TXT、CSV/TSV、JSON/JSONL、HTML/HTM、XLSX。这里的“数据文件”指已有对应解析器的静态文件，不是任意二进制文件，也不代表自动连接数据库、在线 API 或云盘。

实现落在入库解析入口：每种格式先用适合其容器的解析方法提取内容和位置，再生成统一的 `SourceBlock`，复用现有文档版本、解析版本、切块、Embedding、Milvus/PostgreSQL 索引、问答快照和引用校验。这样只维护一条检索与问答链；新格式不会绕过权限、版本或证据边界。

```text
上传白名单与文件大小检查
  -> 按扩展名选择格式解析器
  -> SourceBlock（原文文本 + 章节/行号/字段路径）
  -> 版本化切块与字符范围映射
  -> Embedding + Milvus 向量索引 + PostgreSQL 全文索引
  -> 固定快照检索与逐论点原文引用
```

## 格式与定位

| 格式 | 解析方式 | 引用位置与限制 |
| --- | --- | --- |
| PDF | PyMuPDF 按页读取文本块，保留块顺序和坐标；可检测的有边框表格按首行表头、后续数据行生成结构块，并保留每行 bbox | 显示 PDF 页序；双栏和无边框表格需对照原文；扫描件 OCR 不支持 |
| DOCX | `python-docx` 读取段落和表格；标题样式更新章节名 | 按章节/摘录定位；不支持旧 `.doc` |
| Markdown | 按标题、空行和围栏代码状态组织段落 | 按章节定位；不做完整 Markdown AST 解析 |
| TXT | 按空行切成段落 | UTF-8/UTF-8 BOM；按段落摘录定位 |
| CSV/TSV | 标准库 `csv.reader`，第一条非空记录为表头，每行转成“列名: 值” | 保留源行号；最多 100,000 条记录、1,000 列 |
| JSON | 递归遍历对象和数组，只将非空标量叶子转成块 | 保留对象键和数组下标路径；最多 100,000 节点、深度 64 |
| JSONL | 逐行解析 JSON，再按字段路径生成标量块 | 同时保留物理行号和字段路径；格式错误报告行号 |
| HTML/HTM | 标准库 `HTMLParser` 提取静态文本、标题、表格单元和图片 alt | 不执行 JavaScript/CSS、不加载外链；跳过 script/style/noscript/svg/template，以及用 `hidden`、`aria-hidden` 或常见行内样式标记隐藏的元素。外部样式表或 CSS class 控制的可见性无法判断 |
| XLSX | `openpyxl` 只读工作簿，按工作表和表格行读取；第一条非空行作为表头 | 保留工作表和行号；包含隐藏工作表；公式按公式文本索引、不求值 |

除 PDF 外，响应中的 `page_count` 为 null，引用使用章节、表格行或字段路径，不伪造页码。非 PDF 引用的位置标签对应统一来源块中的结构位置；字符范围是来源块文本的 Unicode 字符下标，可供服务端逐字校验摘录。

## 文件边界与防护

上传扩展名必须在 `SUPPORTED_SUFFIXES` 白名单中，默认单文件上限为 40 MB。文本类使用 UTF-8/UTF-8 BOM 解码并拒绝 NUL；DOCX/XLSX 初步检查 ZIP 特征，随后仍由格式解析器验证包结构。仅靠扩展名或 ZIP 文件头不足以证明文件有效。

XLSX 使用 `read_only=True`，并限制 100 个工作表、每表 100,000 行/1,000 列、累计 2,000,000 个单元格、ZIP 展开体积 80 MB 和单项压缩率 200。原因是上传内容会在 Celery worker 中解析；限制可以在文件损坏或异常压缩时尽早停止，降低 CPU、内存和解压资源被单个任务占满的风险。任务取消和预算中断信号需要继续向上传播，不能被格式错误处理吞掉。

解析限制也明确了能力边界：旧 `.xls`、扫描件 OCR、无边框 PDF 表格恢复、XLSX 公式求值、HTML 浏览器渲染和外部资源加载、数据库/API 在线拉取都没有实现。PDF 表格检测只使用 PyMuPDF 的线条策略；未检测到时保留普通文本块，不会猜列或生成 OCR。XLSX 的公式文本不是计算结果；隐藏工作表会被索引。超过 XLSX 单项压缩率上限的合法但高度重复内容也可能被拒绝，这是资源防护与兼容范围之间的取舍。

## 面试解释

- **为什么在解析入口扩展？** PDF、JSON、CSV 和工作簿的结构差异很大，需要各自正确的读取器；统一成 `SourceBlock` 后，权限、版本、检索与引用继续走同一套逻辑。PDF 表格行复用相同的版本、快照及引用检查，没有另建问答通路。
- **为什么保留行号和字段路径？** 搜索结果应能回到团队原始资料。表格列值、JSON 键路径和工作表行号比虚构页码更有用，也让引用可以人工核对。
- **为什么给工作簿加大小和压缩限制？** ZIP 容器压缩后的文件体积不代表解压后的资源消耗。解析发生在异步 worker，明确上限能控制单个上传任务占用的资源。
- **为什么不计算公式或运行 HTML？** 本功能是检索入库，不是电子表格计算引擎或浏览器。执行动态内容会改变安全边界和结果来源；保留静态公式文本与 HTML 标记更容易复现和解释。
- **为什么不是“任意数据都能输入”？** 每一种文件容器都要有解析器、位置映射和错误处理。无解析器的二进制、在线数据库/API 以及扫描图片不会因为扩展名改名就变成可靠证据。
