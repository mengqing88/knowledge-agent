# 版本组合、升级验证与回退

日期：2026-11-12。以下为本地项目发布流程规范，未实施真实灰度或生产回滚。

1. 保留应用源码副本及哈希/可获取提交、Python/前端锁文件、迁移 head、部署配置引用；容器固定 digest 并保留可拉取镜像。当前目录不是 Git 仓库，Compose 使用镜像标签，哈希清单只识别版本，不能恢复丢失源码、依赖包和镜像。模型仅有供应商别名时明确无法冻结权重。
2. 每次实验记录 `QuestionRun.config` 的 manifest、快照、提示词正文/Schema、服务身份、运行/重试策略及价格来源。密钥只保留变量引用。可选 MCP 配置/角色和端点另存版本，不把一次工具批准当作长期授权。
3. 升级前在数据库副本跑迁移，建立同题配对基线；开发调参后才运行冻结集。先跑权限、撤权、引用、版本、取消、未知用量、预算、降级和事故回归，再做人工质量、费用与延迟比较。门槛必须先定，安全硬失败立即阻断；关键场景退化即使平均分提高也停止升级并定位。
4. 本地只向限定测试账号和隔离知识库开放候选版本；当前无自动灰度平台。记录版本组合、逐题差异、放行人和证据路径。相同配置不保证模型输出逐字一致，合理查询/调用顺序可以不同。
5. 回退前停止创建/领取新任务，处理或取消在途运行，等待旧 worker 停止；未知外部操作先核对回执。旧 worker 不能凭旧 attempt 发布。应用/Provider/依赖变化时，旧清单运行被拒绝，需重新创建问题；读取历史记录不会重新调用模型。
6. 迁移 0004 保留反馈和调用审计，不提供破坏性 downgrade。先确认旧应用能否读新列/新状态；数据库破坏性变更需备份、恢复演练或向前修复。不能仅回退 Python 文件就宣称数据库已回滚。
7. 检索规则/Embedding 变化建立新索引和新快照；保留旧原文/索引用于历史引用。若需恢复旧知识版本，必须明确重新启用策略和授权，不能让在途任务悄悄切换。外部工具已提交写入需要第三方状态核对与业务补偿，本地 checkpoint 无法撤销远端事务。

发布记录建议字段：release_id、代码/依赖/镜像/迁移身份、模型及服务身份、提示词/Schema、索引及快照、工具配置与权限版本、题集哈希、逐项门槛、结果、异常/未知项、放行与停止决定、回退目标和验证产物。当前仅有 run 级清单及上述规范，未实现发布台账 API 或环境自动重建。
