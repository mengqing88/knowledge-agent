# 团队知识库问答评测要求

日期：2026-11-12。本文为规范，不是实测成绩。题集、人工标注与真实服务仍待准备。

## 1. 任务集与冻结

- 开发集允许虚构教学材料，明确 `fictional=true`、`human_reviewed=false`，只能使用 `--allow-dev`。
- 正式集至少 30 道独立人工审核题，来自实际获授权材料。保留 question_id、文档/解析/索引快照、题集 SHA-256、审阅人标识/时间、引用原文和无答案检查范围。`human_reviewed=true` 只是声明，不能替代审阅证据。
- 覆盖单文档事实、跨文档条件比较、可比条件下冲突、部分可答、材料无答案、指代澄清；恶意材料指令、跨库/跨用户访问、被撤权、过时版本、伪造引用、模型/向量服务故障另外建立控制集。
- 冻结后不逐题调整提示词；调参用开发集。失败、超时、取消与缺失产物保留，不删题凑分。

## 2. 对照及归因

同一冻结问题与快照配对运行 `baseline_rag/full_agent/without_verifier`。固定代码、锁文件、模型/服务身份、提示词、Schema、生成上限、预算和重试策略；记录 manifest、attempt 和降级。当前运行器按固定模式顺序执行；真实延迟实验应预先安排交错或随机顺序与重复次数，避免时段负载混杂。当前框架不能代替纯全文/纯向量/混合检索三组实验，也不能用于计算“代码修复成功数”。

| 失败层 | 独立证据 |
| --- | --- |
| 检索 | 人审相关块清单，对照检索排名及实际进入 sources 的原文；命中块不代表被生成节点使用 |
| 规划 | 比较问题对象、条件和必需子问题；不给模型自评作 gold |
| 参数/权限 | Schema 与业务校验、请求未发出的断言、跨租户及撤权负例 |
| 执行 | 调用开始/结束、HTTP 尝试、worker attempt、异常与终态；技术失败不能记成正确拒答 |
| 生成/核验 | 人工逐论点核对内容、条件和引用语义，区分相关性、支持关系、遗漏和错误批准 |

## 3. 指标、分母与门槛

| 指标 | 定义 | 当前实现 |
| --- | --- | --- |
| 技术完成率/失败率 | completed 或 failed/全部分配题；取消和缺失单列，缺失按失败计 | report.py 客观计数 |
| 正确拒答率 | 正常完成且确属无答案的正确拒答/人工确认无答案题 | 状态匹配为代理指标；语义正确仍待人工确认 |
| 误拒答率 | 正常完成却返回 insufficient/人工确认可回答题 | 自动状态计数；漏答原因另查 |
| 引用语义支持率 | 人工支持的引用关系数/全部需核查引用关系数 | 待人工标注，报告 null；无引用时 N/A，不能算 100% |
| 必答点覆盖率 | 人工确认覆盖的必答点/全部必答点 | 待人工标注，报告 null；缺引用和空答案单列 |
| 首查询 Hit@5 | 每道有标签题的首 attempt、首轮、第一条请求 top 5 有相关块则命中；分母为全部有标签题，缺失计未命中 | report.py 探索性计数及缺失数；不是全子查询指标，不得填 Recall@5 |
| Recall@5 | 每查询 top 5 命中相关块数/该查询全部相关块数，再按预定方式宏平均 | 需要完整相关块标签；只有一条参考摘录不能代表全集 |
| 参数/工具正确率 | 独立确认工具及参数正确的调用数/全部应调用样本 | 主问答为固定 ScopedTools；外部 MCP 需单独测试，当前无正式成绩 |
| 错误接受/安全硬失败 | 错误论点被批准；越权、伪造证据发布、未经批准外部写等逐项计数 | 控制测试+人工核查；任何安全硬失败阻断发布 |
| Token/估算费用 | 全 attempt、重试和 Embedding；未知单列，估价写明价格版本/币种 | run accounting 已实现；汇总已知 Token 小计，同币种且全部可估时汇总，否则费用 null |
| 端到端 P95 | 有记录的全部尝试耗时最近秩 `ceil(.95*n)`；报告 n 与缺失数 | report.py 已实现；小样本不可外推生产 SLA |

控制集的已定义不变量要求全部通过，安全硬失败为 0。质量、延迟和费用的具体数值门槛须在正式实验前由评测负责人按题集和演示环境填写并冻结，当前没有经确认的数值目标。不得将清单例子中的 82%、16/30→22/30、96% 倒推为成果；总体上升不能覆盖关键权限或已知事故场景退化。

## 4. 结果与证据

每个实验目录保存 manifest、逐题文件、运行/调用身份、完整 trace、取消回执/未知状态、人工评分表与汇总；失败文件也保留。`evaluate_case` 在轮询失败/超时后尝试取消并仍抓 trace，取消响应丢失记 unknown，不等于后台已停止。采集器崩溃可能漏文件，汇总要显式计缺失。

正式人工表至少包含 question_id、claim/evidence ID、相关性/支持/条件/覆盖判断、评分人、时间、分歧处理和原始依据。独立验收不能由 Verifier 的批准位替代。没有实际运行就不发布分子分母或提升百分比。

## 5. 真实依赖验收

本机 Docker Engine 29.7.2 已用于代码修复扩展的合成端到端控制验收；它不能替代真实论文问答或 PostgreSQL/pgvector、Redis/Celery 的整栈验收。代码修复容器使用固定镜像 ID、禁网、只读文件系统和资源限制，控制测试验证 Git 元数据/密钥不可见及超时清理。SQLite、FakeProvider 和真实 Docker 控制测试是不同证据，不能互相替代。
